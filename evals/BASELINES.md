# Baselines — 怎么证明 China Legal OS 真的比普通 AI 更好

一个法务工作系统声称自己有用，是廉价的。这份文件定义**怎么验证**。

方法形态借鉴 `evan66547/Contract-Reviewer-Agent-Eval` 的多层能力对照实验；**不借鉴它的分数**（自评、无第三方审计）。

---

## 1. 三档

同一批用例、同一个模型、同一套判据，只改变"给了模型什么"。

| 档 | 配置 | 代表什么 |
|---|---|---|
| **Baseline-0** | 裸模型。把 `user_message` 原样发过去，无任何系统提示 | 用户直接问 ChatGPT/Claude |
| **Baseline-1** | 单个"资深中国企业法务/律师"人设 Prompt，300-500 字，无 Gate、无 references、无 schema | 网上流传的法律 Prompt、大多数法律 Skill 仓库的实际水平 |
| **CLOS** | China Legal OS 完整管线 | 本项目 |

**变量控制**：三档必须用同一个模型、同一个温度、同一批输入。任何一项不同，比较就失效，必须在报告中声明。

Baseline-1 的人设 Prompt 固定写死并存档在 `evals/runner/baseline-1-prompt.md`，不得为了让 CLOS 好看而故意写差。**它应该是一个诚实的、水平不错的单体 Prompt。**

---

## 2. 判据

三档用**完全相同**的判据：

- Layer 1：十条 must-not，一票否决（`RUBRIC.md` §Layer 1）
- Layer 2：七维 100 分（`RUBRIC.md` §Layer 2）
- 用例自带的 rubric_items

**主指标是 Layer 1 通过率，不是 Layer 2 平均分。**

---

## 3. 预期与证伪

### 预期

| 指标 | Baseline-0 | Baseline-1 | CLOS |
|---|---|---|---|
| Layer 1 通过率 | 低 | 中 | **应显著高** |
| M2（自产案号）违规率 | 高 | 高 | **应接近 0** |
| Layer 2 平均分（仅 Layer 1 通过者） | — | 中 | 高 |
| "今天该做什么"完备率 | 低 | 中 | 高 |

### 证伪条件（重要）

如果出现以下情况，说明 CLOS 的设计**没有起作用**，应回到 Phase 7 修结构而不是加文字：

| 观察 | 说明什么 | 该修什么 |
|---|---|---|
| Layer 2 分数拉开，但 Layer 1 通过率与 Baseline-1 接近 | Gate 没有生效，赢在"写得更全"而不是"更可靠"——而后者才是这个 OS 存在的理由 | **G1-G4 的判定与拦截逻辑** |
| M2 违规率没有显著下降 | R3 案号禁令没有被真正执行 | `source-policy.md` R3 的措辞与 G2 的 BLOCKED 动作 |
| CLOS 在 Lane A 用例上分数反而更低 | 过度工程化，把简单问题做成了报告 | `legal-router.md` 的 Lane 判定 |
| CLOS 的 `missing` 项显著多于 Baseline-1 但结论质量未提升 | 变成了一个只会要材料的系统 | `fact-engine.md` §4 提问纪律 |
| 三档在某个模块上无差异 | 该模块的 workflow 没有提供实质约束 | 该模块 `references/<module>.md` |

**证伪条件写在前面，是为了防止评测变成自我证明。**

## 4. 报告纪律

评测报告必须包含：

1. **失败归类**：区分「真实缺陷」与「可辩护的判断差异」，分别计数
   （借鉴 `awesome-legal-agent-templates` 的 `VERIFICATION.md`——它诚实地说明 9/410 断言失败是判断差异而非结构性失败）

2. **根因分类**：每个失败标注 `workflow / gate / routing / schema / 知识` 之一
   Phase 7 只允许针对根因改结构。**"再加一段提醒"视为未解决。**

3. **未覆盖范围**：哪些模块、哪些场景没有测

4. **变量声明**：模型、版本、温度、日期、`RETRIEVAL_MODE`

5. **强制免责**：

> 本结果为自评，无第三方审计，用例由本项目自建。
> **不得用作向客户、监管机关或任何第三方的能力证明。**
> 高风险场景（重大交易、监管答复、诉讼策略）应另行补充对抗性测试。

---

## 5. 样本量与诚实

v0.1 的用例规模（每个 Core 模块 ≥3 个，合计约 30-40 个）**不足以支撑统计显著性声明**。

因此报告中：
- 可以说"CLOS 在这 36 个用例中的 Layer 1 通过率为 X"
- **不可以**说"CLOS 比 ChatGPT 准确率高 Y%"
- 差距小于 10 个百分点的，一律描述为"方向性差异，样本量不足以判定"

参照 PLawBench 的量级（850 题 / 约 12,500 条 rubric item）可知：要做出有说服力的能力声明，需要的规模比 v0.1 大一到两个数量级。v0.1 的评测目的是**发现自身缺陷并驱动 Phase 7**，不是对外证明。
