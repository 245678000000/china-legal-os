# compliance

> 面向中国大陆企业法务的业务合规准入、行政监管与日常合规审查核心模块。
> 强化行业资质牌照穿透核验、严格区分“违法禁止”与“监管不鼓励/审慎”、广告营销合规排查、整改责任到岗到人到时限。

---

## 1. Scope

- **处理什么**：
  - 新业务/新产品上线前的法律合规论证与准入可行性排查
  - 行业行政许可、前置/后置审批、特许经营资质牌照排查（ICP、EDI、增值电信、食品经营、网络文化、出版物等）
  - 广告宣传文案、营销活动、价格促销（明码标价、禁止价格欺诈）合规审查
  - 应对行政监管检查、行政问询、行政处罚听证与整改闭环
  - 反洗钱、反商业贿赂、安全生产与环保合规日常筛查
- **不处理什么**：
  - 个人信息与数据出境专门合规（交由 `data-privacy`）
  - 反不正当竞争行为专项排查（交由 `competition`）
  - 刑事犯罪辩护（触发强制升级）
- **常见联动模块**：
  - 协同模块：`data-privacy`、`competition`、`corporate`
  - 交付：`risk-matrix` + `action-plan`

---

## 2. Inputs

- **`required_facts[]`**：
  - `business_description`：拟开展业务的具体模式、交易流程、资金流向、目标用户群
  - `industry_sector`：所属行业（互联网平台、金融科技、医药健康、教育培训、直播电商、制造业等）
  - `target_regions`：业务展业区域（国内特定省市 / 全国范围）
- **`nice_to_have[]`**：
  - `current_licenses`：公司现有资质证照清单与经营范围
  - `marketing_materials`：待发布的广告宣传文案、海报设计图、活动规则
  - `regulatory_inquiries`：监管部门已下发的指导意见、自查通知或问询函
- **`our_side` 必需性**：必需。

---

## 3. Gates

- **G1 事实分类闸**：
  - 必须对业务模式的底层交易逻辑进行事实穿透，严禁仅听信业务部门“我们只是做个撮合平台”的自我定性。
- **G2 法源闸**：
  - 必须清晰区分：**法律法规强制性禁止（违法/无效）** vs **监管部门指导口径/窗口指导/审慎监管（政策不鼓励）**，严禁将二者混淆。
- **G4 交付闸**：
  - 整改方案必须输出明确的**责任岗位、具体动作、整改时限**三要素。

---

## 4. Workflow

### Step 1: 业务模式穿透与监管归口识别
- 穿透业务底层实质：
  - 资金是否经过企业自有账户（排查二清/非法集资/吸收公众存款风险）。
  - 信息如何流转，是否属于平台撮合、自营销售、代理经纪或内容发布。
- 锁定主管监管机构（市场监管局、网信办、工信部、文旅部、金融监管总局、卫健委等）。

### Step 2: 准入许可与牌照合规筛查
- 核验展业所需必备资质：
  - 是否属于《负面清单》禁止或限制投资领域。
  - 增值电信业务许可证（ICP / EDI 区分：仅提供信息发布用 ICP；涉及第三方入驻交易平台必须办理 EDI）。
  - 特殊行业许可证（网络食品交易第三方平台备案、网络文化经营许可证、药品网络销售备案等）。

### Step 3: 广告与营销合规专项体检
- 依据《中华人民共和国广告法》〔条号未核验〕进行严格筛查：
  - [ ] **极限词禁令**：严禁使用“国家级”、“最高级”、“最佳”、“第一”等绝对化用语。
  - [ ] **虚假宣传与证据支撑**：广告中引用的数据、统计资料、调查结果、文摘、引用语必须真实准确并标明出处；严禁无依据声称“保本高收益”、“治愈率 100%”。
  - [ ] **特殊行业广告禁区**：医疗、药品、医疗器械广告不得利用代言人作推荐；教育培训不得明示/暗示保过保提分。
  - [ ] **价格促销合规**：严禁使用“原价”虚构打折基准（必须有前 7 日最低成交记录）、买一赠一必须明确赠品具体品名及数量。

### Step 4: 风险属性分级（严守定性纪律）
- **红色类别（法律明确禁止/非法）**：如无证从事特许经营、传销、非法集资、虚假广告造成人身损害。动作：**严禁上线，立即终止**。
- **黄色类别（监管审慎/政策收紧）**：如业务处于灰色监管边缘、地方执法口径不一。动作：**调整产品文案与交互流程，设立风控隔离**。
- **绿色类别（合规可做）**：在现有许可范围内正常展业。

### Step 5: 整改责任与落地行动计划（Actionable Remediation）
- 编制落地整改表格，明确每一项合规改造的具体责任人：
  - 动作：修改 App 交互流程 / 申请补办许可证 / 撤换广告物料 / 建立合规台账
  - 责任岗位：产品经理 / 市场部负责人 / 法务专员 / 运营总监
  - 时限：当日立即下线 / 3个工作日内完成整改 / 15日内提交资质申报。

---

## 5. Output

- 交付格式：`Risk Matrix` + `Action Plan`
- 遵循 Schema：`schemas/risk-matrix.schema.json` 与 `schemas/action-plan.schema.json`
- 交付物必须涵盖：Review Basis、业务准入资质匹配表、广告合规风险点清单、处罚后果预估（没收违法所得、倍数罚款、停业整顿）、整改 Action Plan。

---

## 6. Escalation

- **触发条件**：
  - 拟展业模式涉及非法吸收公众存款、集资诈骗、非法经营罪等刑事罪名风险
  - 收到市场监督管理、公安等行政机关出具的《立案调查通知书》或《行政处罚听证告知书》
  - 涉及可能被处以吊销许可证、责令停业整顿或主管人员市场禁入等重大处罚
  - 涉及全网全渠道广告重大翻车与群体性消费者维权事件
- **升级路径**：E2 法务合规总监 → E3 业务分管 VP → E4 CEO / 董事会合规委员会
- **所需材料**：业务方案白皮书、行政调查通知书原件、涉案营收流水统计、应急整改预案
- **时限要求**：收到监管调查文书后 2 小时内紧急升级响应

---

## 7. Eval hooks

- [ ] **Must-Not 1**：必须清晰区分“法律明文禁止”与“监管不鼓励/审慎态度”，严禁混为一谈。
- [ ] **Must-Not 2**：整改行动计划中禁止缺少“责任岗位”和“完成时限”。
- [ ] **Must-Not 3**：在审查互联网平台撮合交易时，禁止遗漏 EDI 许可证与平台商户管理义务的核验。
