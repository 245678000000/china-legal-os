# Evidence

**OS 级基础能力，不是诉讼模块的附属品。**

合同审查要问"这条违约责任真要用时，你能证明损失吗"；合规要问"你能证明取得了单独同意吗"；劳动要问"你能证明制度公示过吗"。这些都不是诉讼问题，但全都是证据问题。

企业法务最常见的失败不是法律分析错，而是**法律分析对、证据拿不出来**。

---

## 1. 何时运行

| 场景 | 是否强制 |
|---|---|
| Lane C | **强制**，输出完整 Evidence Matrix |
| 争议、商业秘密、劳动解除、侵权 | **强制** |
| 合同审查 | 对每个 High/Critical 条款做**可执行性检查**（§5） |
| 合规、尽调 | 对每个"已合规"的结论做**可证明性检查** |
| Lane A | 不出矩阵，但结论仍受四元 min 规则约束 |

## 2. Evidence Matrix

| 待证明事项 | 举证责任 | 当前证据 | 证据强度 | 缺失证据 | 下一步 |
|---|---|---|---|---|---|

### 列的定义

**待证明事项** — 来自 Reasoning 的要件（`legal-reasoning.md` §2），一个要件一行。不是"证明我们有理"，而是"证明客户名单采取了相应保密措施"。

**举证责任** — `我方 / 对方 / 待定`
- `待定` 必须给出判断路径：这个问题由什么决定、怎么查
- **不得跳过这一列**。谁举证决定了这一行的战略意义：如果举证责任在对方，我方证据薄弱不一定是问题

**当前证据** — 逐项列出，注明来源和形式（原件/复印件/截图/电子数据/证人）。**没有就写"无"**，不写"有待补充"。

**证据强度** — 四级：

| 强度 | 含义 |
|---|---|
| `充分` | 单独或组合足以支撑该要件，且形式合法、来源可靠 |
| `较强` | 能支撑，但存在可攻击点（形式瑕疵、来源单一、需要补强） |
| `薄弱` | 有指向性但不足以单独支撑 |
| `无` | 没有 |

**缺失证据** — 具体到"是什么文件/记录/数据"，不写"相关证据"。

**下一步** — 必须是可执行动作：做什么、谁做、什么时候前做完、需要什么配合。

## 3. 时限敏感动作单独置顶

以下动作晚做就做不成，必须从矩阵中抽出来单独列在最前面：

- 电子数据固定（服务器日志、邮件、聊天记录、下载记录 —— 会被覆盖或删除）
- 公证 / 时间戳
- 现场证据保全
- 证人接触（记忆衰减、立场变化）
- 诉前财产保全（对方可能转移）
- 网页/页面内容取证（对方随时可下线）

格式：

```
【时限敏感 — 建议 3 个工作日内完成】
1. 调取该员工离职前 30 天的 OA/邮箱/代码仓库/CRM 访问与下载日志
   责任人：IT + 法务    需要：HR 提供账号与在职期间
   若不做：日志按 IT 留存策略可能已被覆盖，最核心的"获取行为"证据将永久缺失
```

**必须写"若不做会怎样"** —— 这是让业务方真的去做的唯一有效写法。

## 4. 证据强度反向约束结论（G3）

Evidence 的产出直接进入四元 min 规则：

```
overall_evidence_ceiling = 各关键要件证据强度的最小值映射
  充分 → Confirmed        较强 → Probable
  薄弱 → Conditional      无   → Unverified
```

**只看关键要件**。非关键要件证据薄弱不封顶整体结论，但要在矩阵中标出。

### G3 证据闸

```
[ ] 每个关键要件都有一行（含"无证据"这一评估结果）
[ ] 每一行都分配了举证责任
[ ] 结论确定性 ≤ overall_evidence_ceiling
[ ] 时限敏感动作已抽出置顶，并写明不做的后果
[ ] 缺失证据具体到文件/记录名称
```

未过 → **下调结论并注明下调原因**。不得保留一个证据支撑不足的强结论。

## 5. 非争议场景的证据检查

### 合同审查：条款的可执行性

对每个 High/Critical 条款问三件事：

1. **触发时能否证明？** —— "对方迟延交付按日万分之五计违约金"：交付日期以什么为准？验收记录谁保管？没有验收流程时怎么证明迟延？
2. **损失能否量化举证？** —— 约定了赔偿实际损失，实际损失怎么证明？有没有可替代的定额条款？
3. **对方的抗辩事实我方能否反驳？** —— 对方主张不可抗力/我方原因导致迟延，我方有没有过程记录？

发现"条款写得很好但用不出来"时，这本身就是一个 High 级发现，且修改方向通常是**增加过程记录义务**而不是提高违约金。

### 合规：已合规结论的可证明性

任何"我们已经合规"的结论都要问：监管来查时，你拿什么证明？

- 已取得单独同意 → 同意记录的存证方式、留存期限、可否复现当时的界面
- 已完成个人信息影响评估 → 报告在哪、谁签的、什么时候
- 已履行告知义务 → 版本记录、生效时间、用户可及性

**"制度上有"和"能证明做过"是两件事。** 后者才是合规。

## 6. 常见判断错误

| 错误 | 纠正 |
|---|---|
| 把"我方掌握的材料"等同于"证据" | 证据要能证明**具体待证事项**。一堆聊天记录不指向任何要件，就不是证据 |
| 不区分举证责任 | 我方薄弱但责任在对方，与责任在我方，战略完全不同 |
| 证据强度按"数量"评 | 十份指向同一薄弱环节的材料，仍是薄弱 |
| 忽略形式合法性 | 电子数据的来源、完整性、获取方式合法性，会直接决定能否采纳 |
| 缺失证据写"需补充相关材料" | 无法执行。必须具体到文件名/系统名/时间范围 |
| 把"下一步"写成"建议收集证据" | 同上。必须有责任人和时限 |
| 只评估我方证据 | 必须评估对方可能持有什么，以及对方举证不能时的后果 |
