# legal-research

> 面向中国大陆企业法务的法律问题深度研究与依据梳理模块。
> 严守无检索源（`RETRIEVAL_MODE: none`）下的反幻觉纪律：严禁编造案号，条号必带〔条号未核验〕，分歧必标 Unverified。

---

## 1. Scope

- **处理什么**：
  - 法律条文、司法解释、监管规则的规则内容梳理与适用条件分析
  - 新旧法衔接、法律溯及力及过渡期适用问题
  - 法律行为/商业模式的合法性与效力定性
  - 司法实践观点分歧与裁判倾向的检索指引梳理
- **不处理什么**：
  - 具体合同或诉讼文书起草（分别交由 `contract-drafting` / `dispute`）
  - 终局商业决策与审批拍板（交由 `business-decision`）
  - 非中国大陆法域的具体法律解释（先声明超出范围）
- **常见联动模块**：
  - 上游：任一提出法律疑问的业务场景
  - 下游：`legal-memo`（承载交付物）、`evidence`（评估事实是否满足法定要件）、`business-decision`（将法律依据转化为业务动作）

---

## 2. Inputs

- **`required_facts[]`**：
  - `research_question`：明确的法律问题或业务疑难点
  - `jurisdiction`：适用法域（默认：中国大陆 CN-mainland）
  - `relevant_time`：行为发生时间或待评价事实的时间节点（决定适用新法或旧法）
- **`nice_to_have[]`**：
  - `business_context`：业务背景、交易目的或行业惯例
  - `known_authorities`：用户已知或提及的政策依据
- **`our_side` 必需性**：
  - 纯法理/法源梳理时非必需；但若涉及利弊倾向与抗辩空间，必须明确我方身份。

---

## 3. Gates

- **G1 事实分类闸**：将用户在咨询中附带的事实区分为 Confirmed / Alleged / Disputed / Missing。
- **G2 法源闸（强制重点）**：
  - 每个法律结论必须具备法源标注（名称 + 规则内容 + Level + Status）。
  - 所有出现的具体条号一律格式化为 `《X法》第 N 条〔条号未核验〕`，且不得以条号为唯一支撑。
  - **R3 绝对禁令**：不得自行产出任何非来自用户材料的案号、案件名称或裁判要旨。
  - 观点分歧与实践倾向强制标为 `Unverified`。
- **G3 证据闸**：对法律适用所需的前提事实进行证据充分度核验。
- **G4 交付闸**：交付物必须包含 Review Basis 抬头与待核验清单。

---

## 4. Workflow

### Step 1: 争点命题精确化
- 将宽泛问题（如“竞业限制协议怎么签有效”）转化为 1~3 个可判断真伪的具体争点命题（如“未约定竞业补偿金标准是否导致竞业限制条款自始无效”）。

### Step 2: 时间基准与溯及力核验
- 核查事实发生时点与法律法规生效/修订时点。
- 遵循“法不溯及既往”原则，识别新旧法衔接规则（如民法典施行前后合同效力衔接、新公司法施行前后出资期限衔接）。

### Step 3: 法源层级与规则内容提取
- 按法律位阶由高到低（法律 → 行政法规 → 司法解释 → 部门规章 → 地方性法规）梳理规则。
- 提取规则实质构成：`行为前提 / 适用主体 → 行为模式（可以/必须/禁止） → 法律后果（无效/可撤销/行政处罚/民事赔偿）`。
- 标明法源等级（L1 用户材料 / L2 官方法源 / L3 官方案例 / L4 辅助资料）。

### Step 4: 案例检索指引生成（无检索源模式标准产出）
- 不虚构判决，而是针对核心争点输出可供人工核验的检索路径：
  ```
  【建议检索】争点：未约定补偿金时竞业限制协议的效力
    目标平台：人民法院案例库 (rmfyalk.court.gov.cn) / 中国裁判文书网 (wenshu.court.gov.cn)
    推荐检索词：竞业限制 补偿金 未约定 效力 劳动合同法司法解释
    核验目的：确认裁判机关是否认可按法定标准补发补偿金即可维持协议效力
    影响：若核验不通过（确认直接无效），则不能基于协议要求前员工承担竞业违约金
  ```

### Step 5: 观点分歧与实务倾向标注
- 当存在裁判观点分歧（如各地法院裁审口径差异）时，如实陈述分歧双方的逻辑，标为 `[模型知识-未核验]`，严禁静默偏向一方。

### Step 6: 法律涵摄与实务建议
- 将梳理出的要件与用户事实进行严密涵摄，得出初结论并移交 G3/G4 门禁。

---

## 5. Output

- 交付格式：`Legal Research Memo`（法务备忘录）
- 遵循 Schema：`schemas/legal-memo.schema.json`
- 关键模块包括：Short Answer、Certainty 标签与封顶项、Authorities 清单、Search Guidance 检索指引、Detailed Analysis 深度分析、Verification Worklist 待核验清单。

---

## 6. Escalation

- **触发条件**：
  - 涉及刑事合规或潜在刑事责任界定
  - 涉及国家安全、数据出境安全评估或关键信息基础设施
  - 涉及反垄断执法或重大反不正当竞争行政调查
  - 核心依据存在重大利益分歧或现行法空白
- **升级路径**：升至法务负责人 / 聘请外部专业执业律师出具专项咨询
- **所需材料**：完整的业务背景材料、交易全套协议、争议时序表、待确认法律问题清单
- **时限要求**：在业务定案前 3 个工作日内完成升级介入

---

## 7. Eval hooks

- [ ] **Must-Not 1**：禁止仅罗列法条名称而未陈述具体规则内容（违反 R2 规则）。
- [ ] **Must-Not 2**：禁止产出任何未在输入材料中出现的案号（M2 正则强校验）。
- [ ] **Must-Not 3**：禁止将模型知识的实践观点标注为已核验（禁止 Promotion）。
- [ ] **Must-Not 4**：当法律条文可能已失效或被新法修正时，禁止遗漏标注时效存疑。
