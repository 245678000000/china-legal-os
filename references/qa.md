# Legal QA

四个 Gate 的判定细则与回退协议。

**总原则：Gate 拦截后不得停止工作。** 一个只会说"我需要更多信息"的系统对企业法务没有价值。

---

## 1. Gate 判定

### G1 事实分类闸 — 法律分析之前

```
[ ] 全部输入事实已归入 confirmed/alleged/disputed/missing/assumption 之一
[ ] 我方立场 已确定，或已作为唯一阻塞问题提出
[ ] 相关时点 已确定或已标为 assumption
[ ] 用户的法律定性已全部归入 alleged
[ ] disputed 项已并列两侧，未静默选边
[ ] missing 已区分 critical / non-critical
[ ] assumption 已写明推翻条件
[ ] critical 缺失已在当前回复中提示
```

**失败动作**：缺 `我方立场` → 提问（唯一允许的阻塞提问）。其余 → 补齐分类后继续，不停工。
细则见 `fact-engine.md`。

### G2 法源闸 — 输出法律结论之前

```
[ ] 每个法律结论有 authority 标注（名称 + 规则内容 + Level + Status）
[ ] 出现的每个条号都带〔条号未核验〕
[ ] 每个条号都已进入 待核验清单
[ ] 没有条号是唯一支撑（R2）
[ ] 不存在非 L1 来源的案号 / 案件名称 / 裁判要旨（R3）
[ ] 命中 Currency Trigger 的结论强度 ≤ Conditional（R4）
[ ] L4 材料没有被当作法律依据陈述
[ ] 没有把 unverified 标为已核验（禁止 promotion）
```

**失败动作**：
- R3 命中 → **BLOCKED**。删除案号，改写为「检索指引」，然后继续
- 其余 → 自动补标注 / 自动降级，记入 QA 日志，继续

细则见 `source-policy.md` §7。

### G3 证据闸 — 定稿结论之前

```
[ ] 每个关键要件都有证据评估（含"无证据"这一结果）
[ ] 每一行都分配了举证责任
[ ] 结论确定性 ≤ overall_evidence_ceiling
[ ] 四元 min 规则已应用，且已写出封顶项
[ ] 时限敏感动作已抽出置顶，并写明不做的后果
[ ] 缺失证据具体到文件/记录名称
```

**失败动作**：下调结论并注明下调原因。**不得保留证据支撑不足的强结论。**
细则见 `evidence.md` §4。

### G4 交付闸 — 输出正式交付物之前

```
[ ] Review Basis 抬头存在（含 RETRIEVAL_MODE 与 company context 加载状态）
[ ] 待核验清单存在（Lane B/C，且已按影响严重程度排序）
[ ] 输出符合对应 schema
[ ] Escalation 判定已做出（含"无需升级"这一结论）
[ ] Escalation 内容不是"建议咨询律师"
[ ] High/Critical/BLACK 结论已过 Red Team，且已回答"是否下调"
[ ] 命中强制升级清单的事项未给出终局结论
[ ] 风险点都连着后果和动作，没有孤立的风险等级
[ ] 没有 0-100 分数
[ ] 对外文本不含内部策略分析和证据弱点
[ ] 免责声明在末尾，只有一处
```

**失败动作**：BLOCKED，回退到具体 Engine 修复；修复后重跑 G4。

---

## 2. 回退协议

BLOCKED 时输出必须包含三件事：

```
【被拦截】G2 法源闸 — 输出中出现了非材料来源的案号
【已完成】要件拆解与事实分类已完成，见下方分析（该案号引用已移除，改为检索指引）
【下一步】next_owner: 法务经办
          next_action: 按检索指引在人民法院案例库检索，找到后回填可提升该结论至 Probable
```

**禁止**：只说"无法完成"然后结束。
**禁止**：把失败结果写成已完成。

回退目标：

| 失败项 | 回退到 |
|---|---|
| 事实分类不全 | Fact Engine |
| 路由错误 / secondary 无贡献 | Legal Router |
| 依据缺失 / 出现案号 | Research + Source Policy |
| 结论强于证据 | Evidence（然后重新合成结论） |
| 缺对抗检验 | Red Team |
| 缺"今天做什么" | Business Decision |
| 格式/抬头/清单缺失 | Output Formats |

---

## 3. 自检顺序

QA 按此顺序跑，早失败早回退，避免在错误的基础上继续修：

1. G1（事实错了，后面全错）
2. 路由合理性（primary 是否正确，每个 secondary 是否有独立贡献）
3. G2（依据）
4. G3（证据）
5. Red Team 是否已跑且产出已回流
6. Business Decision 七问是否齐全
7. G4（交付形态）

---

## 4. 输出状态

| 状态 | 含义 |
|---|---|
| `PASS` | 全部通过 |
| `FIXED` | 自动修复后通过。**必须列出修复了什么**（用户有权知道结论被下调过） |
| `BLOCKED` | 需要外部输入。必须给 next_owner + next_action |

`FIXED` 的可见形式：抬头下方一行

```
说明：本文中 2 处法律依据因无法核验，结论确定性已由 Probable 下调为 Conditional。
```

---

## 5. QA 不做什么

- 不做法律正确性的实质复核（那需要人）
- 不因为"看起来专业"就放行
- 不因为用户催就跳过 Gate
- 不在 BLOCKED 时把已完成的工作丢掉

---

## 6. 用户要求跳过时

用户说"不用检索了直接写""不用那么严谨""直接出正式版"：

**明确写出被拦截的门禁名称和后果，然后在允许范围内继续做。**

> 可以直接出，但有两处我不能跳过：
> ① 第 12 条的赔偿责任判断依赖法条，无检索源下只能标 `Conditional`，我会照常标注；
> ② 你要的"类似判例"我不能编，会给你检索指引，你或实习生 20 分钟能查到。
> 其余部分现在就写。

不说教，不重复解释，做完该做的事。
