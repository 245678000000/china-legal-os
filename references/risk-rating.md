# Risk Rating

全模块共用的风险语言。**不输出 0-100 分数**——分数伪装成可比较、可加总的量，而"合规风险 30 分"与"财务风险 25 分"不可通约，且会被业务方当阈值用（"80 分以上就签"）。

---

## 1. 五档

| 档 | 含义 | 默认动作 |
|---|---|---|
| **BLACK** | 违反法律强制性规定 / 该约定不产生效力 / 行为本身不被允许 | **必须改**；改不了就换交易结构或不做 |
| **Critical** | 可能危及业务存续、重大财务敞口、刑事或重大监管处罚风险 | 立即升级 + 暂停相关动作 |
| **High** | 重大不利后果但可控 | 升级 + 限期处理 |
| **Medium** | 需要处理但不阻塞 | 纳入处理计划 |
| **Low** | 知悉即可 | 记录 |

### BLACK 为什么必须独立成档

中国法下"约定无效"是一个**性质**判断，不是程度判断。把它塞进"High"会导致错误的动作——法务会去谈判争取，而正确动作是"这样写没用，必须换写法或换结构"。

BLACK 的典型形态：违反效力性强制性规定的约定 · 法律明确禁止的行为 · 需要行政许可而未取得 · 排除对方主要权利的格式条款 · 变相规避法定义务的安排。

**判断 BLACK 要谨慎**：不确定是"无效"还是"可能被认定无效"时，标 Critical 并写明"存在被认定无效的风险，需核验"，不要滥用 BLACK。

## 2. 决定等级的五个维度

| 维度 | 问什么 |
|---|---|
| Probability | 这个风险实际发生的可能性 |
| Legal Impact | 法律后果的严重程度（无效、赔偿、行政处罚、刑事） |
| Financial Impact | 财务敞口量级，尽量给区间 |
| Business Impact | 对业务连续性、客户关系、上下游的影响 |
| Reputation | 舆情、客户信任、监管记录 |

不加权、不求和。**取最严重的那个维度定档**，并在理由中说明是哪个维度驱动的。

## 3. 三个独立修饰符（不进等级计算）

| 修饰符 | 取值 | 为什么单列 |
|---|---|---|
| **Reversibility** 可逆性 | 可逆 / 部分可逆 / 不可逆 | 不可逆的 Medium 比可逆的 High 更需要在决策前想清楚 |
| **Evidence Strength** 证据强度 | 充分 / 较强 / 薄弱 / 无 | 决定"这个风险我们能否防守"，而不是"风险有多大" |
| **Legal Certainty** 法律确定性 | 五级确定性之一 | 决定"这个判断本身有多可靠" |

**为什么不折叠进等级**：一个"Medium 但不可逆且证据薄弱"的事项，在决策上比"High 但可逆且证据充分"更需要谨慎。平均成一个等级会把这个信息丢掉。

标准写法：

```
风险：High（驱动维度：Financial Impact，敞口约 200-500 万）
      不可逆 · 证据薄弱 · 法律确定性 Conditional
```

## 4. 强制升级清单

命中任一 → **不得给出终局结论**，必须升级并说明升给谁、需要什么。

- 刑事风险
- 监管调查 / 处罚答复
- 证券与信息披露
- 反垄断
- 数据出境 / 大规模敏感个人信息
- 并购、融资、重组
- 群体性劳动争议
- 人身伤亡事故
- 对外公开声明
- 重大诉讼策略
- 证据保全或灭失风险

命中时的正确输出：完成能做的分析 + 明确标注 `需升级` + 给出**给外部律师/上级的问题清单**（不是"建议咨询律师"，而是"需要律师回答的具体三个问题"）。

以下属于**拒绝**而非升级（见 `legal-honesty.md` §7）：规避法律强制性规定、伪造证据、逃税、损害第三方合法权益。

## 5. 升级链

`company/company-legal-context.md` 未填写时使用下列默认占位，并在交付物中标注为默认值：

| 层级 | 默认岗位 | 触发 |
|---|---|---|
| E1 | 法务经办 | Medium |
| E2 | 法务负责人 | High · 偏离 playbook 且超出 acceptable fallback |
| E3 | 业务分管领导 | 商业让步超出 playbook · 需要业务方承担风险 |
| E4 | 总经理 / 董事会 | Critical · BLACK · 超授权金额 |
| E5 | 外部律师 | 命中 §4 强制升级清单 · 关键依据需权威确认 |

### Escalation 必答四问

```
升给谁    ：法务负责人（E2）          ← 岗位，不是"律师"
触发条件  ：赔偿责任无上限，超出 playbook 中"以合同总价为限"的可接受区间   ← 可判定
需要材料  ：合同全文、报价单、本次审查意见、对方历史合作记录
时限      ：本周五前，因对方要求下周一回签
```

**以下不是 Escalation**：
- "建议咨询专业律师"
- "需要进一步评估"
- "请业务方确认"（没说确认什么、由谁确认、确认了会怎样）

## 6. 风险与动作必须成对出现

单独的风险等级没有价值。每个风险点必须连着写：

```
风险点：第 12 条约定我方对因交付物导致的第三方索赔承担无上限赔偿责任
等级  ：Critical（驱动：Financial Impact，理论敞口不封顶）
        不可逆 · 证据强度不适用 · 法律确定性 Probable
后果  ：一旦发生第三方专利索赔，赔偿额可能远超合同总价 80 万
修改  ：（可直接插入的条款文本）
退让  ：若对方坚持不设总上限，退而争取"以合同总价的三倍为限，且排除间接损失"
升级  ：E2 法务负责人；若对方拒绝全部方案则 E4
```

## 7. 禁止

| 禁止 | 替代 |
|---|---|
| 0-100 分数 / 百分比 / 星级 | 五档 + 三修饰符 |
| "存在一定法律风险" | 给档位 + 驱动维度 + 后果 + 动作 |
| 把所有条款都标 High | 校准：一份正常商业合同通常只有 1-3 个 High 以上。全是 High 等于没有分级 |
| 只标风险不给修改 | 见 §6 |
| 因为不确定就往高标 | 不确定应体现在 `Legal Certainty` 修饰符，不是抬高档位 |
